# TECHNICAL_DOCUMENTATION

## System Specifications & Visual Architecture

### Section 1: Microservices Architecture (FastAPI)
The Heart Disease Prediction System leverages a robust, cloud-agnostic microservices architecture powered by **FastAPI**. 
* **ASGI Asynchronous Handling:** At its core, FastAPI provides asynchronous request handling via ASGI (Asynchronous Server Gateway Interface). This routes Node.js frontend requests seamlessly to the PostgreSQL persistence layer, HuggingFace inference endpoints, and Groq LLM pipelines, supporting heavy parallel processing.
* **The Internal Gateway Pattern:** The backend implements an API Gateway architecture (`internal_gateway.py`), acting as a secure intermediary layer. Access is strictly governed via timing-safe `X-INTERNAL-API-KEY` comparisons, decoupling internal machine learning execution from public-facing client requests.

### Section 2: Tabular ML Engine (CatBoost)
The primary predictive engine for tabular clinical data assesses patient risk based on 11 distinct clinical features (Age, Sex, Chest Pain Type, Resting BP, Cholesterol, Fasting Blood Sugar, Resting ECG, Max Heart Rate, Exercise Angina, Oldpeak, and ST Slope).

* **The Explainability Mandate (CatBoost vs. StackingClassifier):** 
While experimental analysis on `1000heart.ipynb` indicated high performance from ensemble models (StackingClassifier 93.70%), the system deploys **CatBoost** (Accuracy: 92.44% - 95.0% depending on validation folds). Deploying CatBoost—rather than a StackingClassifier—was a calculated engineering tradeoff. In the medical domain, AI explainability is legally and ethically mandated. CatBoost provides native, high-speed compatibility with the **SHAP TreeExplainer**. This enables real-time generation of waterfall visualizations dictating *why* a patient received a specific diagnosis, effectively eliminating the "black-box" latency inherent to Deep Stacking models.

![Feature Importance / SHAP Plot](./visualizations/shap_summary_plot.png)

* **Decision Threshold Optimization (Youden's J Statistic):** 
The model implements a dynamic probability cutoff using Youden’s J statistic threshold analysis at **0.41**. By shifting the threshold away from the default 0.50, the model prioritizes **Recall (97.0%)** and **ROC-AUC (0.977)** over raw Accuracy. In medical diagnostics, a False Negative (sending a sick patient home) is fatal. The 0.41 cutoff minimizes these fatal False Negatives, mapping predictions into strictly defined dynamic risk brackets: Low Risk (0-0.40), Moderate Risk (0.41-0.60), and High Risk (0.61-1.0).

### Section 3: Deep Learning ECG Engine (xresnet1d101)
The Deep Learning ECG pipeline is designed to emulate a digital cardiologist, assessing raw waveform data to output independent multi-label probabilities across 71 distinct SCP codes.

* **WFDB Pipeline & Preprocessing:** 
Hospitals natively export 12-lead ECGs in the PhysioNet WFDB format (`.dat` and `.hea` file pairs). The backend dynamically ingests these files, extracts the native sampling frequency from the `.hea` header, and applies `scipy.signal.resample` to normalize the waveform to exactly **100Hz**. Subsequently, `StandardScaler` is applied across the leads for amplitude normalization, correcting voltage fluctuations from different hardware sensors. The system strictly asserts 12-lead truncations, rejecting invalid 8-lead formats.
* **Neural Network Architecture (1D ResNet-101):** 
The ECG classification model uses a **1D ResNet with 101 layers** (`xresnet1d101`). Traditional Recurrent Neural Networks (LSTMs) suffer from vanishing gradients when processing long time-series data like 10-second ECG signals (1000 data points per lead). The ResNet architecture utilizes skip-connections (residual blocks), enabling the neural network to learn deep temporal, beat-to-beat spatial relationships across 101 layers without degradation.
* **Multi-Label Inference:** 
The output layer utilizes 71 independent Sigmoid activation functions rather than a Softmax function, outputting probabilities for 71 separate SCP abnormalities simultaneously. This enables the model to correctly identify co-occurring pathologies (e.g., Atrial Fibrillation combined with a Myocardial Infarction).

### Section 4: Generative AI Explainer (Llama-3.3-70b-versatile)
The patient-facing diagnostic report is orchestrated by the `Llama-3.3-70b-versatile` model deployed via Groq's high-speed inference pipeline.

* **Prompt Engineering & Context Injection:** 
The LLM utilizes Few-Shot prompting injected with strict system constraints. Rather than inferring blindly, the prompt concatenates the patient's exact vitals (Age, BP, Cholesterol, etc.) with the exact empirical SHAP impact scores generated by the CatBoost model. This guarantees the LLM's explanation is mathematically grounded in the features that actually drove the AI's prediction.
* **Retrieval-Augmented Generation (RAG):** 
The LLM's system prompt is augmented with the `ecg_diagnosis_kb.py` knowledge base. By grounding the LLM strictly within this pre-approved medical taxonomy, we prevent out-of-domain hallucinations and enforce scientifically accurate vocabulary.
* **Medical Safety Layer (The "Kill-Switch"):** 
To prevent the LLM from acting as a prescribing doctor, a rigorous, two-pass Safety Layer is implemented. 
  1. **Pydantic Schema Enforcement:** The LLM is forced to output a strictly formatted JSON object dictating the Explanation and exactly 5 actionable, non-pharmacological recommendations.
  2. **Regex Sanitization:** Before the payload is returned to the user, an aggressive `_UNSAFE_PATTERNS` regex pipeline scans the output. Strings matching medical definitive claims (e.g., "definitely diagnosed", "you have a heart attack") or pharmacological prescriptions (e.g., "take Aspirin 81mg", "start Lipitor") are instantly blocked and intercepted with a `[medically reviewed]` mask.
